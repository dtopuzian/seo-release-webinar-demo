# Релиз, который выглядит исправным

Учебный магазин «СЛОЙ» показывает одну ошибку: новая версия работает для
покупателя, но запрещает поисковику индексировать важные страницы. Два процесса
выпуска демонстрируют, как SEO-проверка останавливает такую версию до публикации.

- [Магазин без проверки](https://shop.93-99-105-4.sslip.io:9443/)
- [Магазин с проверкой](https://shop.93-99-105-4.sslip.io:9443/checked/)
- [Три кнопки запуска](https://github.com/dtopuzian/seo-release-webinar-demo/actions)
- [Бот SEO Checker](https://t.me/seo_release_checker_bot)

## Показать за 5–7 минут

Перед показом запустите **«3. Вернуть обе витрины к v1»** и дождитесь результата.
На обеих витринах в верхней полосе должна быть надпись **«Версия v1»**.

1. Откройте первую витрину, каталог и товар. Добавьте товар в корзину.
2. В Actions выберите **«1. Выпустить без SEO-проверки» → Run workflow**.
   После успешного шага публикации обновите магазин: теперь вверху v2,
   каталог и корзина продолжают работать.
3. В DevTools найдите `meta name="robots"`: значение `noindex,follow` запрещает
   индексацию. Оно появилось на главной, в каталоге и на четырёх карточках товаров.
4. Откройте вторую витрину и запустите **«2. Выпустить с SEO-проверкой»**.
   Шаг SEO-проверки станет красным, публикация будет пропущена.
5. Покажите сообщение в Telegram и ссылку на настоящий отчёт. На второй
   витрине остаётся v1: ошибочная версия не была опубликована.
6. В обычном интерфейсе бота запустите проверку первой витрины по её корневому
   адресу. В отчёте откройте meta robots: так ошибку можно обнаружить и вручную.

После репетиции снова запустите **«3. Вернуть обе витрины к v1»**. История
запусков и отчёты сохраняются. Корзины живут в браузере: очистите их отдельно
в обеих витринах перед следующим показом.

## Что проверяется на самом деле

На сервере заранее установлены две неизменяемые версии магазина. GitHub
передаёт только фиксированную команду выбора, проверки или публикации версии.
Проверка запускает тот же SEO-движок, который используется ботом, и требует
HTTP 200, полный HTML и отсутствие общего meta noindex/none на шести важных
страницах. Ошибка или неполный результат останавливает публикацию.

Обе сцены используют одинаковый bad/v2. В нём SEO-различие одно — общий
meta robots noindex на шести страницах. Также честно меняется видимая версия.
Контент, корзина, SVG и разрешающий `robots.txt` одинаковы. Страницы «О бренде»
и корзины остаются `index,follow`.

Исходники в этом репозитории позволяют изучить и локально собрать витрину.
Workflow переключает уже установленные серверные артефакты: правка HTML в
GitHub сама по себе не заменяет их. SHA серверного движка закреплён в
`DEMO_RUNTIME_SHA` и отличается от SHA коммита этого репозитория.

У выпуска без SEO-проверки нет отдельного gate-отчёта. У заблокированного
выпуска он есть. Сообщение Telegram отражает свежую серверную квитанцию;
ошибка доставки сообщения не разрешает публикацию. При недоступном сервере
уведомление прямо говорит, что результат не подтверждён.

Noindex не удаляет страницы из поиска мгновенно: последствия зависят от
повторного обхода. Это демонстрация обнаружения дефекта и решения о выпуске,
а не эксперимент с настоящим поисковым трафиком. Сам по себе noindex не всегда
ошибка — здесь явно задано требование индексировать важные страницы.

## Настройка ведущим

Workflows запускаются вручную в основной ветке репозитория
`dtopuzian/seo-release-webinar-demo`. Нужны четыре repository Actions secrets:

| Secret | Значение |
|---|---|
| `DEMO_SSH_KEY` | Полное содержимое выделенного OpenSSH-ключа демо без парольной фразы. |
| `DEMO_SSH_KNOWN_HOSTS` | Заранее проверенная запись ключа SSH-хоста. |
| `DEMO_TELEGRAM_TOKEN` | Токен бота для уведомления ведущего. |
| `DEMO_TELEGRAM_CHAT` | Числовой ID личного чата ведущего. |

Секреты вводятся в Settings → Secrets and variables → Actions. Ключ не хранится
в репозитории: на runner он записывается во временный файл с правами 0600 и
удаляется после операции. Адресат Telegram задаётся только секретом; формы
ввода произвольного получателя нет.

Движок должен быть уже установлен на сервере с SHA
`2559b7978fd5bf49c4b9b18b18840d30992eb675`. Клиент сверяет этот SHA, run ID,
сцену, версию и digest артефакта. Подготовка сервера в этот репозиторий не входит.

Три workflows используют одну очередь: одновременно выполняется один запуск,
остальные ждут. Во время показа используйте только эти кнопки; параллельные
команды оператора или другого CI не входят в очередь GitHub. Сброс двух витрин
состоит из двух публикаций: при сбое одной другая может уже обновиться.
Последний шаг сброса показывает свежую квитанцию каждой витрины в Actions;
сообщения Telegram при сбросе не отправляются.

Workflows не загружают artifacts в GitHub и не устанавливают Python-пакеты.
Единственный внешний action — [официальный checkout v7.0.1](https://github.com/actions/checkout/releases/tag/v7.0.1),
закреплённый полным SHA `3d3c42e5aac5ba805825da76410c181273ba90b1`.

## Локальный просмотр и проверки

Python 3.12+, только стандартная библиотека:

```sh
python build_shop.py good .work/good
python build_shop.py bad .work/bad
python -m http.server 8787 --bind 127.0.0.1 --directory .work/good
```

Открыть `http://127.0.0.1:8787/`. Выходной каталог сборки должен быть новым или
пустым. Одинаковый артефакт работает в `/` и `/checked/` без переписывания HTML.
Каталог доступен без JavaScript; корзине нужен JavaScript и HTTP.

```sh
python -I -B -m unittest discover -s tests -v
```

Тесты проверяют состав и digest артефакта, точное отличие v1/v2, относительные
ссылки, квитанции, ошибки SSH, запрет ложного PASS, честные уведомления,
временные файлы ключа и зависимости workflow. Сеть и настоящий Telegram в
тестах не используются.

Бренд, товары и цены вымышлены. Иллюстрации — локальные SVG. Покупок, оплаты,
форм персональных данных, внешних CDN и аналитики нет.
